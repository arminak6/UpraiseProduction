# A1 integration and operation

Implemented: A1 POST /v1/documents and original A4 GET /v1/jobs/{job_id}.
Source language, PDF-only processing, old Nova/Docling/Titan pipeline and
separate durable PostgreSQL jobs were approved by the user on 2026-10-02.
The diagram's original audit-only PostgreSQL boundary is explicitly extended.
On 2026-10-02 the user requested removal of the A1 Ingestion Guard and job_id.
On 2026-10-06 the user restored job_id in the A1 response body, matching the
original Word contract. The Ingestion Guard remains removed.

## Request and response

Multipart form fields:

| Field | Meaning |
| --- | --- |
| course_id | Middleware-authorized Moodle course |
| activity_id | Moodle activity containing the material |
| language | Source language tag, e.g. it, en-GB, fr, de; mapped to supported OCR codes |
| source_ref | Moodle file ID as an opaque string; never a host path |
| content_hash | Required opaque source revision/hash string, 1..200 characters; not verified |
| version | Optional upstream revision label |
| file | One readable, unencrypted PDF; declared MIME and filename extension are not checked |

Moodle's native SHA-1 contenthash can be forwarded as content_hash. It remains
declared metadata and is not compared with the uploaded bytes. The module
separately computes actual SHA-256 as source_hash for extraction IDs, checkpoints
and byte-aware retry identity. File IDs are scoped to the configured caller:
use a distinct integration client per Moodle instance. Middleware remains
responsible for professor permissions and authoritative Moodle source identity.
Declared metadata alone is not authentication or cryptographic origin proof.

Example request from Middleware through the configured TLS gateway:

```sh
curl --cert middleware-client.crt --key middleware-client.key \
  -H "Authorization: Bearer $API_TOKEN" \
  -H "Idempotency-Key: course25-file48127-revision1" \
  -F "course_id=25" -F "activity_id=310" -F "language=it" \
  -F "source_ref=48127" -F "content_hash=<Moodle contenthash>" \
  -F "version=1" -F "file=@teaching.pdf;type=application/pdf" \
  https://ai.example.edu/v1/documents
```

HTTP 202 body is exactly:

```json
{"document_id":"<document UUID>","job_id":"<ingestion job UUID>"}
```

Location identifies the original /v1/jobs/{job_id} A4 polling URL, using the
same job_id as the JSON body. Use document_id for A2 material deletion and A3
source selection; use this ingestion job_id for A4 status and A6 cancellation
or acknowledgement. A5 uses the separate lesson job_id returned by A3.
202 means PDF bytes and job metadata
are durably saved, not that extraction succeeded. Identical Idempotency-Key,
caller, input metadata and PDF bytes return the original document_id, job_id and
polling URL, including legacy accepted requests after this update; conflicting
reuse is 409. The first submission selects the pipeline.
Without a key, each accepted upload receives a fresh identity as in Uprise/v2.

For the original signed-Moodle-URL mode, send application/json with the same
metadata and moodle_url instead of file. The API downloads/stages the bytes
before acceptance, preventing expiry from losing an accepted job. Source hosts
and response MIME are not allowlisted. HTTPS is required; redirects, userinfo,
non-443 ports and unsupported encoding are rejected. DNS addresses are checked
and pinned while TLS
validates the original hostname. Private endpoints require explicit allowed
CIDRs. The source server validates its URL authorization/signature when serving
the file; no Moodle-specific signature key/scheme was supplied for local
cryptographic verification. Credentials/signed URLs are not persisted in jobs.

## INGRESS configuration

Required environment settings are documented in root .env.example. OAuth
access tokens are validated against HTTPS JWKS using pinned RS256/ES256
algorithms, issuer/audience and required exp/iat/sub claims. Authorized client
IDs are allowlisted. Tokens must carry a string scope containing
documents:write for A1/A2 delete, documents:read for A2 list, jobs:read for A4,
and jobs:write for A6,
plus upraise_courses as an array
of allowed course IDs. Arrange this claim with the Moodle/Middleware identity
provider. A4 permits only the originating client and an authorized course.

TLS terminates at the deployment gateway, which must verify client certificates
and overwrite X-SSL-Client-Verify (SUCCESS) and X-SSL-Client-Fingerprint. Configure
trusted gateway peer CIDRs and allowed certificate fingerprints. Only trusted
peers may supply these assertions. Uvicorn proxy-header processing is disabled
to prevent forwarded client IPs from impersonating the gateway. Keep the API
behind that gateway/private network. Missing integration configuration returns
503 INGRESS_NOT_CONFIGURED; forged/untrusted assertions return 403. No bypass
or fabricated production credentials are included. The localhost health utility
does not grant access to document APIs.

## Processing and status

The Ingestion Guard was removed by explicit user decision on 2026-10-02.
A1 does not scan metadata, native/OCR text or enrichment output for instructions,
reject embedded active content, compare an expected hash, check PDF magic bytes,
or require declared PDF MIME/filename extension or a source-host allowlist.
services/pdf/input.py retains PDF readability, unsupported-encryption and
size/page limits as processor support checks. OAuth/mTLS INGRESS and the
downloader's HTTPS/TLS/DNS-pinned network handling remain in place.
Vision prompts still request source-faithful extraction. Native source text is
retained; language does not request translation. The current pipeline version
is pdf-ingestion-v1.4, with a configuration signature appended to stored records.

Docling 2.115.0 performs whole-PDF reading-order extraction, accurate tables,
OCR, formula enrichment and visual crops. Nova Pro recovers empty formulas and
inline mathematics; Nova Lite optionally describes figures. All available math
crops and figures are processed, with no per-document count or minimum figure
width/height cutoff. Visual failures retain source evidence
and warnings; embeddings/publication failures prevent DONE. Default limits are
100 MB and 500 pages. OCR language mappings are in services/pdf/languages.py;
unsupported languages are explicitly rejected instead of silently using English.

Section-aware chunks retain atomic tables/figures/formulas/code, repeated heading
context and overlap only on forced splits. Target 600 estimated tokens with 60
overlap. The old whitespace estimate is bounded into short spans to protect
scripts without spaces, and oversized contexts fail instead of exceeding budgets.
The estimate is local, not Titan's tokenizer. Titan V2 uses normalized 1024D
float vectors. Input is never silently truncated.

Qdrant payload retains course_id, document_id, page and section, plus activity_id,
source_ref, language, content_hash/version, source_hash, page_numbers, heading_path, logical
chunk IDs and source-element IDs/types. A cross-page Docling element preserves
all provenance pages/bounding boxes and per-region crops in extraction artifacts; page is the first
source page and page_numbers is the complete citation set. Physical point IDs
are isolated by worker attempt. A document is usable only with no deletion request, when its job is DONE
and the Qdrant ingestion_token matches the job's active_attempt. Future retrieval
must enforce this boundary; an unfiltered Qdrant scan may include incomplete
attempts after a crash. Do not interpret INDEXED payload status as activation.
content_hash preserves the caller's declared value; source_hash is the actual
SHA-256 computed from the staged PDF. Citation/page provenance is retained as
extraction output even though document provenance checks have been removed.

A4 returns job_id, document_id, status, step, progress (0..1), attempts, error,
result, timestamps, cleanup_pending and acknowledged. Status is
QUEUED/RUNNING/DONE/FAILED/CANCELLED; steps identify
parse, enrich, chunk, embed, store and retry waiting. DONE result contains page
and chunk counts, warning count, pipeline version, quality_status, quality_summary
(total/auto_checked/unverified/needs_review element counts) and requires_review.
The review flag indicates NEEDS_REVIEW; false does not establish source accuracy.
Errors expose codes only.
Audit records cover accepted work, verified indexing, retries and failures.
They do not contain document text, filenames, URL tokens or learner data.
Global audit/read/rejection policy beyond this A1 lifecycle remains deferred.
See [A6](a6.md) for cancellation, receipt acknowledgment and temporary-output cleanup.

## Source fidelity

The v1.4 pipeline preserves source_text and source_structured_content alongside
accepted original_text/structured_content. Generated candidate_text and
candidate_description remain in preparation artifacts even when rejected.
These source snapshots are parser/OCR output, not an assertion that parsing was
correct. The original PDF and native Docling JSON remain the visual evidence.

Each source_regions entry records its page, bounding box, character span and
crop path. Every visual provenance entry is cropped directly from its page;
multiple regions on the same page and across pages stay separate. Missing,
invalid or unavailable evidence prevents automatic acceptance. Embedded item
images cannot stand in for complete page-region evidence.

Inline recovery uses nonoverlapping, complete character-span mappings and
replaces only source-aligned mathematical spans, retaining surrounding prose
verbatim. Dropped/changed prose or changed source numeric sequences require
review, including cases where parser errors may explain the discrepancy.
Balanced LaTeX and valid table structure are basic checks, not accuracy proofs.
Existing Docling formulas are checked too. Tables compare both Markdown and
HTML against the source, including headers, cells, units and relationships.

A separate Bedrock comparison pass checks complete crop evidence for formulas,
inline rewrites, tables and generated figure descriptions. It checks symbols,
superscripts/subscripts and operators, and exact figure labels, directions and
connections. Only a complete, readable, supported result with no issues is
accepted. Malformed/truncated/provider-failed results require review. Complete
evidence exceeding provider image/size limits requires review rather than
truncation or downsampling. Successful comparison caches include all ordered
crops, pages, candidate text, content type, model and prompt version.
UPRAISE_FIDELITY_VISION_MODEL_ID configures this pass (default Nova Pro); it is
part of the pipeline signature. This can use the same model family as extraction
and share its mistakes. It reduces risk, but does not prove fidelity.

Quality is separate from QUEUED/RUNNING/DONE/FAILED/CANCELLED:

| Quality | Meaning |
| --- | --- |
| UNVERIFIED | Content has no complete recorded source comparison; ordinary parser prose remains in this state. |
| AUTO_CHECKED | The recorded automated structural/source checks passed; no guarantee or human approval is implied. |
| NEEDS_REVIEW | Missing evidence, a discrepancy, uncertainty or a failed comparison requires attention. |

Rejected AI output does not replace parser text or enter chunk text. Unresolved
formula/figure regions retain source-review placeholders and provenance for
retrieval rather than silently disappearing. Native parser content can still
be indexed with its uncertainty recorded. Figure captions/text outside the
checked image remain UNVERIFIED, even if the derived description passed; its
separate description_quality is retained in element metadata. Quality covers
element content, not user metadata, inferred heading hierarchy or the factual
truth of statements already present in the PDF.

Chunks/Qdrant carry aggregate quality, per-element quality and source regions
keyed by element ID. NEEDS_REVIEW takes precedence over UNVERIFIED, then
AUTO_CHECKED; mixing regions never upgrades uncertain content. Future teaching
consumers must inspect these states and source evidence, and must not silently
present UNVERIFIED/NEEDS_REVIEW material as verified facts. No human-approval
workflow or universal accuracy guarantee is implemented. Thresholds/policy need
evaluation on a manually checked corpus of varied layouts, scans and languages.

Existing indexed documents keep their earlier quality (missing quality means
UNVERIFIED); upgrading the code does not recheck them. Re-ingest their PDFs to
apply v1.4. Prepared checkpoints require the current signature and actual source
SHA-256 before reuse. Drain old-signature queues or keep compatible workers;
no database schema migration is needed for the quality fields.

## Recovery and limits

Workers claim rows transactionally with leases and attempt tokens, renew leases
while processing, and reject stale ownership at publication. Extraction/model
calls run outside the job transaction. The worker service supervises each attempt
in a fresh spawned process, with the child holding its artifact lock while it can
write. The supervisor measures elapsed time independently of processing callbacks
and lease heartbeats; a blocked converter cannot renew its way past a deadline.
Qdrant publication/count verification
and audit acknowledgement run under the current owner's row lock; then the
job commits DONE. Cross-store atomic transactions are unavailable: a crash can
leave inactive vectors or an INDEX_VERIFIED audit event without DONE. Recovery
replays safely under a new attempt; old attempts are isolated and cleaned after
successful completion. No exactly-once claim is made for AWS requests.

Processing has workload-based phase budgets and an absolute wall-clock attempt
limit. Each phase deadline starts on entry and is not restarted by repeated
progress. Budgets are clipped to the total limit, which starts when the child is
launched and includes initialization and publication. Docling also receives the
page-based parse timeout.

| Budget | Default seconds | Environment settings |
| --- | --- | --- |
| Entire attempt | 43,200 (12 hours) | UPRAISE_JOB_TIMEOUT_SECONDS |
| Parse with OCR | 180 + 30 per validated PDF page | UPRAISE_PARSE_TIMEOUT_BASE_SECONDS, UPRAISE_PARSE_TIMEOUT_PER_OCR_PAGE_SECONDS |
| Parse without OCR | 180 + 10 per validated PDF page | UPRAISE_PARSE_TIMEOUT_BASE_SECONDS, UPRAISE_PARSE_TIMEOUT_PER_PAGE_SECONDS |
| Enrichment | 180 + 180 per estimated generation/comparison request | UPRAISE_ENRICH_TIMEOUT_BASE_SECONDS, UPRAISE_ENRICH_TIMEOUT_PER_REGION_SECONDS |
| Embedding | 120 + 90 per chunk | UPRAISE_EMBED_TIMEOUT_BASE_SECONDS, UPRAISE_EMBED_TIMEOUT_PER_CHUNK_SECONDS |
| Child startup | 300 | UPRAISE_WORKER_STARTUP_TIMEOUT_SECONDS |
| Initialization or phase without a workload estimate | 300 | UPRAISE_WORKER_PHASE_TIMEOUT_SECONDS |
| Chunking | 300 + 10 per validated PDF page | UPRAISE_WORKER_PHASE_TIMEOUT_SECONDS, UPRAISE_PARSE_TIMEOUT_PER_PAGE_SECONDS |
| Publication | 300 + 5 per chunk | UPRAISE_WORKER_PHASE_TIMEOUT_SECONDS; total attempt limit still applies |

The supervisor checks at UPRAISE_WORKER_SUPERVISOR_POLL_SECONDS (default 1).
Ownership reads run in a read-only daemon thread, with at most one outstanding
read reused across jobs. UPRAISE_WORKER_STATUS_TIMEOUT_SECONDS (default 2)
sets the database statement timeout. Network or connection cleanup can take
longer, but the supervisor never waits for that reader. If ownership stays
unverifiable for an entire lease period, it stops the child with
OWNERSHIP_CHECK_TIMEOUT. Cancellation, deletion or transferred
ownership stops the child. Termination allows
UPRAISE_WORKER_TERMINATE_GRACE_SECONDS (default 5) before a forced stop; cleanup
and failure persistence follow confirmed child exit. Linux also kills the child
if its supervisor dies. Supervisor activity alone updates the service health
heartbeat during supervised processing.

A deadline reports PROCESSING_TIMEOUT and uses the existing bounded retry/backoff
policy, ending FAILED when attempts are exhausted. Outcome persistence and A6
cleanup also run in a supervised recovery child, limited to the smaller of the
fallback phase budget and the lease duration (120 seconds by default). A blocked
database/vector/audit call in recovery cannot stall the supervisor. Failure persistence rechecks
the original lease: it cannot replace cancellation, deletion, another worker's
ownership or a completed job. If outcome persistence is unavailable, the expired
lease remains recoverable. Source PDFs and completed preparation checkpoints are
preserved. Stopping a local child cannot guarantee that an AWS request already
submitted stops executing or billing.

These defaults are conservative starting values, not measured performance limits.
Enrichment counts every candidate-generation crop plus a separate comparison
request, including native formulas and tables. Multiple source regions increase
the estimate. The existing per-region setting now supplies time per estimated
request. This preserves generous large-document allowances for the added checks;
additional provider calls increase processing time and cost.
Prewarm model weights and tune them against representative large PDFs and provider
latency. Budget changes do not alter the extraction pipeline signature, skip
source regions or require a database schema migration. Stop old unsupervised
workers before replacing the service.

Successful preparation is persisted for reuse on publication retry. Workers
claim only their pipeline/config signature; drain queues before upgrading or
keep compatible workers running. Terminal failures do not restart endlessly;
temporary failures get bounded backoff, normally three attempts. Submission
with an uncertain DB commit preserves staged bytes. Such orphan evidence needs
operator reconciliation rather than automatic deletion that could lose a job.

Artifacts are retained by default, matching the old extraction approach; set
UPRAISE_ARTIFACT_RETENTION_DAYS only after agreeing retention. Cleanup removes
terminal-job/completed-deletion working files only, not indexed content or database history.
Source material is still authoritative in Moodle. This Compose design uses
one PostgreSQL server and shared local volumes; replication, backups, gateway,
disk/resource capacity and shared/object storage for multiple hosts must be
configured for deployment. PDF processing is isolated in services/pdf; the
shared format dispatcher is the extension point for later document processors.

Streamlit at localhost:8501 is an optional API Testbench (Compose tools profile),
separate from the final product. It supports A1 uploads/URLs, A2 list/delete, A4 polling, health
and general JSON requests. Configure a token and the HTTPS mTLS gateway in its
sidebar for production authentication. The explicitly approved local testing
mode requires no OAuth/mTLS credentials; see local-testing.md and ../../frontend/README.md.

The real Moodle gateway/issuer and signed-URL scheme have not been supplied,
so that external integration cannot be claimed as tested. Validation uses
synthetic documents and controlled auth fixtures; live AWS/Docling/Qdrant and
PostgreSQL checks are recorded separately.
