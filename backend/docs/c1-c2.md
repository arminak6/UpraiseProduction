# C1/C2 - Operational health and feature availability

C1 and C2 are read-only monitoring APIs. They do not generate content, create
sessions, grant learner consent or report individual job progress (A4 does that).

## C1

`GET /health` returns `200 {"status":"alive"}` without INGRESS or dependency
checks. Docker's backend healthcheck continues to use this endpoint.

`GET /ready` returns a cached, content-free dependency snapshot without INGRESS:

- `200 READY`: checked core storage, collection, workers and providers are available.
- `200 DEGRADED`: core storage is available, but a feature dependency is unavailable
  or unverified. An STT/TTS outage does not remove the whole backend from service.
- `503 NOT_READY`: jobs PostgreSQL, audit PostgreSQL, Qdrant service or artifact
  directory checks failed, are pending, or the monitor snapshot is stale.

The response contains `status`, `checked_at` and a `dependencies` map. Each
dependency has `state: AVAILABLE | UNAVAILABLE | UNKNOWN`, a fixed `reason_code`
and optional `observed_at`. No credentials, database URLs, raw exceptions,
model responses or learner information are returned. `Cache-Control: no-store`.

Checks run outside the request/event-loop path, every 10 seconds by default,
with short connection/statement/network deadlines. Both PostgreSQL databases
are checked for schema and required privileges. Artifact directory checks verify
access, not free disk capacity or every stored file's integrity. Qdrant service
and its configured collection are separate: a missing collection is a feature
limitation, allowing a fresh deployment to accept its first A1 ingestion.

## AWS evidence and workers

Health polling makes **no AWS requests**. It never invokes an LLM, synthesizes
audio, sends a transcript, or uses STS as proof of model permissions.

Normal Bedrock InvokeModel/Converse, Polly SynthesizeSpeech and streaming
Transcribe calls publish content-free outcomes to a bounded PostgreSQL table,
`operational_observations`, shared by the API and workers. Only component,
state, fixed reason, opaque configuration hash and timestamp are stored.
Malformed-request errors do not mark the provider unavailable. Provider status
expires to UNKNOWN after 15 minutes without new evidence; transient transport,
throttling/service failures expire after 30 seconds. Model/region/credential-file
changes isolate observations. Invalid mounted credentials mark providers unavailable.

The lesson supervisor reports a shared heartbeat while idle and while supervising
jobs. A heartbeat older than 150 seconds makes generation unavailable. Unknown
providers are not labelled healthy; C1 can still return 200 DEGRADED. These checks
indicate recent reachability/access, not content quality or a guarantee about the
next request. Best-effort observation writes cannot replace or fail the AI request.

## C2

`GET /v1/status?course_id=test-course` requires service authentication. A supplied course is authorized against the caller's
course claims; omitting it reports global controls only, without enumerating
course overrides. No learner JWT is required for this service-level report.

The response contains `course_id`, `checked_at`, `answers_available`,
`stt_available`, `tts_available`, `generation_available`, `kill_switch_active`
and a `features` map. Each feature reports `enabled`, `available`, `state` and
`reason_codes`. Availability is **true, false or null**: null means UNKNOWN,
not disabled or verified healthy. Disabled/down features still return HTTP200;
authorization/configuration/validation errors use the existing 4xx/503 behavior.

Answers require the exact teaching/source storage, generator/reviewer models and
embedding provider. STT and audible answers depend on the answer pipeline; disabling
voice input leaves typed questions available. TTS includes Polly and narration models.
Full A3 generation additionally needs the worker and TTS enabled/available.
Middleware can adapt controls, but availability never bypasses B1/B4 authorization,
consent, lesson version or source checks. Cached status is advisory; actual requests
remain authoritative and can recover before the next monitor refresh.

## Operator controls

The API and workers use the same Compose environment configuration:

```dotenv
UPRAISE_OPERATIONS_KILL_SWITCH=false
UPRAISE_OPERATIONS_KILL_SWITCH_COURSES=[]
UPRAISE_OPERATIONS_DISABLED_FEATURES=[]
UPRAISE_OPERATIONS_COURSE_DISABLED_FEATURES={"course-1":["stt","generation"]}
```

Supported feature names: `answers`, `stt`, `tts`, `generation`, `adaptive_levels`. Global controls
and course controls combine; a course cannot override a global disable.
Apply environment changes by restarting/recreating the backend and workers together.
[C3](c3.md) adds authenticated, audited runtime controls in shared PostgreSQL;
those changes require no restart. Environment disables remain a safety floor.
GET C2 never changes controls. Deploy identical settings to all processes.
C2's `features.adaptive_levels` reports the B2 adaptation control and storage
availability; it does not claim automatic difficulty switching is implemented.
Shared control-storage failures return sanitized 503 rather than stale enabled flags.

The kill switch rejects new A1/A3/B4 AI work with sanitized 503 `AI_DISABLED`.
Feature guards reject disabled generation before acceptance and block disabled
STT/answers before their provider operations;
disabled TTS preserves checked B4 text with `AUDIO_DISABLED`. A3 requires TTS.
Workers leave disabled-course jobs queued without consuming attempts; cleanup and
delivery stay operational. Configuration changes do not cancel already executing
provider calls. Existing A5 audio, A2/A6 management and B5 session cleanup retain
their original authorization/retention behavior.

Other settings and bounds are documented in `.env.example`: refresh/probe timeout,
provider evidence TTL and worker heartbeat TTL. They do not change pipeline identity.
The observation/control schema migration is additive; existing sources, jobs, text and
course audio are preserved.

## Frontend and local curl

The **Health** page provides explicit liveness, readiness and optional-course
feature-status checks. It displays UNKNOWN and error bodies; navigation/rerenders
do not poll or invoke AI. Changing credentials/course clears previous C2 results.

```powershell
curl.exe -i "http://localhost:8000/health"
curl.exe -i "http://localhost:8000/ready"
curl.exe -i "http://localhost:8000/v1/status?course_id=test-course"
```

These work without credentials only in the already-authorized local test mode.
Production C2 needs the service bearer token and trusted mTLS gateway.
