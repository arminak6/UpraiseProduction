# A8 - List ready generated lessons

The user approved A8 on 2026-10-07 to let the frontend discover lessons already
generated through A3, including jobs submitted through curl. This is an extension
to the original Word baseline. A7 now replaces the selected chunk in its existing
lesson using [the replacement contract](a7.md). A8 lists current prepared lessons;
A7 processing jobs and superseded snapshots are excluded before pagination.

`GET /v1/lesson-jobs` returns a JSON array of lesson summaries. It does not generate
content, return lesson text, open learner sessions or acknowledge receipt.

## Input and access

Normal authoring OAuth/mTLS INGRESS applies. Results belong to the
authenticated client and are restricted to its authorized courses. Optional query
parameters:

| Parameter | Default | Constraint |
| --- | --- | --- |
| `course_id` | All authorized courses | Nonempty, at most 120 characters; requires course access |
| `limit` | 100 | 1 through 100 |
| `offset` | 0 | 0 through 1,000,000 |

Filtering happens before pagination. Results are ordered newest first by creation
time, then job UUID. An empty result is `200 []`. An explicitly unauthorized course returns 403. Invalid parameters return 422,
and unavailable storage returns 503.
Responses use `Cache-Control: no-store`.

## Output and availability

Each summary contains `job_id`, `lesson_id`, `course_id`, `activity_id`, `language`,
`voice`, `learner_level`, `chunk_count`, `status`, `label`, `requires_review`,
`review_issue_count`, `created_at` and `expires_at`.

`teaching_version` identifies the course authoring strategy (`v1`, `v2` or `v3`),
independently of `generation_version: a3-v2`, which identifies the API/alignment
format. Historical requests without a teaching-version field used V1 by contract.
When every stored part in the listed level records the same `teaching_policy`,
that policy is included too (for example `teaching-narration-v2.8`). Missing or
mixed part policies omit this optional field. This reads existing PostgreSQL
provenance without loading course text/audio or regenerating or updating courses.

Only DONE jobs with available output and active, undeleted
DONE source documents belonging to the same client/course are listed. Lesson
output can be unexpired temporary delivery or a saved persistent package; TTL
cleanup alone does not hide saved courses. A6 receipt and content deletion still
hide them. Saved entries omit `expires_at`. See [persistent archive](lesson-archive.md).
Status remains DRAFT and requires human review; ready means ready for preview,
not approved teaching content. Failed, running, cancelled, unsaved expired and acknowledged
jobs are excluded. Duplicate lesson IDs from separate generations have distinct
job IDs and creation times.

A5 remains authoritative when opening a lesson: it rechecks access, source
activation, artifact integrity and audit availability. A job can become unavailable
between listing and playback, or an artifact can be missing/corrupt. The frontend
handles those failures and offers another selection or retry.

## Frontend use and retention

Frontend2's **Preview courses** calls A8 for the course catalog, A5 result for
ordered text and A5 audio for each part. Playback state lives in the browser tab.

The default temporary retention remains 24 hours. With the archive configured,
A5 serves saved packages after this period. A8 does not recover missing old audio
or synthesize new audio from PostgreSQL text. Playback does not send A6 automatically.

## One-line PowerShell curl

```powershell
curl.exe -i "http://localhost:8000/v1/lesson-jobs?course_id=test-course&limit=100&offset=0"
```

Use normal OAuth and the mTLS gateway outside explicit development local-test mode.
