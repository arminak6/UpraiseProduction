# B4 — Learner interruption

`POST /v1/sessions/{session_id}/interrupts` handles an open-ended learner message
using a request-local LangGraph workflow, following original Uprise/v2's semantic
classify → retrieve → respond approach. B1 must already have opened the session.
New responses and successful cached retries return `200`, `Cache-Control: no-store`.
B2 chunk-end decisions and B5 session end are implemented separately; B3 and B6
remain reserved. See [B2](b2.md) for the input-score test threshold and consent.

## Input

JSON text: `request_id` UUID, `chunk_id` UUID, nonblank `text` (at most 6000
characters), optional `playback_offset_ms` nonnegative integer. Extra fields,
client chat history, language/level overrides and missing messages are rejected.

Audio: multipart fields `request_id`, `chunk_id`, optional `playback_offset_ms`,
and exactly one file under **audio**. Only uncompressed mono 16-bit PCM WAV,
8–48 kHz, up to 60 seconds/6,000,000 bytes by default. Text and audio cannot be
combined. Unsupported encoding is `422`; excess size/duration is `413`.
Multipart files remain RAM-spooled within the total body limit, never saved to
disk/S3. Transcribe Streaming receives PCM using the session language and EU
region; the upload is discarded after the request. No transcription batch jobs.
STT additionally needs IAM `transcribe:StartStreamTranscription`; unsupported
languages fail explicitly. EN/IT/FR/DE/ES/PT/NL/JA/KO/ZH are currently mapped.

B4 runs in the backend process, so the backend needs AWS credentials for
Bedrock/Titan/Polly/Transcribe. Compose mounts the existing ignored
`aws_credentials.json` read-only into both the backend and workers. A working A3
worker does not establish that the backend has credentials.

The session supplies exact lesson_job_id/result hash, course/documents,
language, explanatory level and voice. Source queries are rewritten into each
declared source language before Titan embedding when it differs from the lesson.

Production requires the existing service OAuth/mTLS ingress and `sessions:write`,
plus `X-UPRAISE-Session-JWT` matching session/client/learner subject/job/hash/
context/consent and approved lesson. Local JWT-free access is only allowed for a
local preview created by B1. Stored `questions` consent is required for all B4
learner message processing, including STT and player-control interpretation.

## Response

One shape, with no public request-classification `type` or `kind`:

```json
{
  "request_id": "UUID",
  "chunk_id": "UUID",
  "answer_id": "UUID or null",
  "text": "teaching response or null",
  "ssml": "<speak>...</speak> or null",
  "audio": {"media_type": "audio/wav", "encoding": "base64", "data": "..."},
  "visemes": [{"time_ms": 0, "value": "sil"}],
  "sources": [{"document_id": "UUID", "document_version_id": "UUID", "pages": [1], "source_chunk_ids": ["UUID"], "quality_status": "AUTO_CHECKED"}],
  "grounded": null,
  "playback_action": null,
  "warnings": ["GROUNDING_NOT_VERIFIED"]
}
```

`audio` is nullable and contains actual WAV bytes encoded as base64, not a URL.
`text` is the exact teacher turn passed to speech preparation; `audio` voices
that turn using the existing v2/V3 math/SSML adapter. The frontend displays the
text and plays the decoded WAV. Curl prints Base64 unless its response is saved.
`grounded` currently remains null for every response: independent factual
grounding verification is temporarily disabled by the user's 2026-10-07 decision.
Accepted teaching replies include `GROUNDING_NOT_VERIFIED`. Their `sources`
identify the authorized material supplied to the teacher, not independently
verified evidence for every answer claim. The teacher still follows the original
v2 source-based prompt and page-citation instructions. Safety/language review,
authentication, consent, source/version checks and expiry remain enforced.
Source quality warnings remain visible. The replacement grounding strategy is
recorded in the ignored root `FUTURE_UPDATES.md`.

`playback_action` is an optional `{action, rate}` control instruction: `REPLAY`,
`SET_SPEED` (absolute rate 0.5–2), `PAUSE`, `RESUME`. This bounded player contract
does not restrict the learner's natural-language goals. A mixed teaching/player
request can return both. Player-only replies have no new answer/audio; `REPLAY`
uses existing A5 chunk audio. These actions do not advance pages, end the RAM
session or change the stored lecture. Middleware/player applies the instruction.

Polly/math narration reuses the existing V3 preparation and same-SSML viseme
adapter in the B1 language/voice. TTS failure retains the teacher text with nullable
audio and `AUDIO_UNAVAILABLE`. All generated teaching/support/clarification
replies are checked for safety and session language before speech. Rejection
returns a localized safe reply with `ANSWER_SAFETY_REJECTED` and/or
`ANSWER_LANGUAGE_REJECTED`, no source references or player action. Invalid/provider
output-check failures return a sanitized `503`, never an unchecked answer.
Math/source/timing warnings remain visible.

## Flow

1. Frontend pauses current playback; B4 cannot directly stop a browser audio player.
2. Authorize session/consent/chunk; resolve current A5 generation/hash/expiry and
   exact PostgreSQL prepared text, checked against the result's text/provenance.
3. LangGraph STT node transcribes WAV when present; semantic `teacher.classify()`
   understands the current message, exact teaching text and recent RAM dialogue.
4. Player-only requests return a control instruction. Teaching responses always
   receive the current chunk's original Qdrant source evidence. Course questions
   always perform semantic search; other support requests search when useful.
   Authorized PG documents and active ingestion attempts are paired in Qdrant
   filters; document versions must match the pinned lesson. Evidence chunks are
   kept whole within the source context budget; current-source overflow fails.
5. Original v2 `teacher.respond()` uses its native source/dialogue formatting
   and response prompt, plus exact PG context and the session language/level.
   Both questions and support retain that answer after a strict-schema safety/
   language check. The reviewer receives answer/target language, not a factual
   evidence-copy task. Quote/claim/page-grounding gates are disabled; `grounded`
   stays null and sources describe context. Missing source context can still
   return the localized not-covered reply with `ANSWER_NOT_SUPPORTED`.
   Ambiguous/blocked requests clarify/refuse.
6. Prepare SSML from the returned text and synthesize inline speech, recheck expiry/source revocation,
   audit content-free metadata before publication, then update bounded RAM cache.

There is no permanent learner content in PostgreSQL, Qdrant or artifact files.
LangGraph checkpoints and LangSmith tracing are explicitly disabled. Audit stores
IDs, counts/status/warning codes only, never messages, answers, audio or JWTs.

## Retries, concurrency and availability

Reuse the exact `request_id` and payload after network failure. A completed retry
returns the same answer/audio without another model/STT/TTS call or audit event,
after access/lesson validity is checked. Changed payload under the same ID is
`409 INTERRUPT_REQUEST_CONFLICT`. Only the last two responses per session are
cached; a global 32 MiB quota can evict older responses. Known evicted request IDs
return `409 INTERRUPT_RETRY_EXPIRED`, never silently regenerate. At most 100
successful messages per session. Failed provider attempts may be repeated on a
retry; provider calls cannot be made exactly-once across failures/process restarts.

One turn per session; overlap is `409 INTERRUPT_IN_PROGRESS`, Retry-After 2.
Independent sessions can overlap within `UPRAISE_INTERRUPT_MAX_CONCURRENT` (4).
Excess admission is retryable `503`. B4 runs on the backend, separately from A1/A3
worker queues. Provider calls have bounded timeouts; this synchronous JSON version
does not promise a two-second latency or first-audio streaming.

RAM sessions/results disappear on expiry/restart. Session expiry is not renewed.
B5 also clears history/reply audio and rejects late B4 work; see [B5](b5.md).
Expired/deleted/acknowledged A5 output cannot be used to bypass the 24-hour policy
through PostgreSQL. Revoked sources block delivery, including cached answers.

## Local test

Start B1 with `consent_scope:["questions"]`, then obtain `chunk_id` from A5.
Replace SESSION_UUID and CHUNK_UUID with actual values. Use a new request UUID
for each new message, retaining it for retries.

```powershell
curl.exe --% -i -X POST "http://localhost:8000/v1/sessions/SESSION_UUID/interrupts" -H "Content-Type: application/json" --data-raw "{\"request_id\":\"f1316a7f-2dc7-4676-a4cb-53c5ad814e09\",\"chunk_id\":\"CHUNK_UUID\",\"text\":\"Can you explain this in other words?\"}"
curl.exe -i -X POST "http://localhost:8000/v1/sessions/SESSION_UUID/interrupts" -F "request_id=4d606f81-9084-44cc-b919-b153f0187631" -F "chunk_id=CHUNK_UUID" -F "audio=@C:\material\question.wav;type=audio/wav"
```

Streamlit: Start session (B1) → enable Questions consent → Start session → Learner
interrupt (B4) → Load teaching chunks → choose current chunk → send text/WAV.
The test page plays new answer audio and displays player-action instructions.
Alternatively, **Learning → Start course → Interrupt / ask teacher** opens an
integrated question panel, stops lesson audio, and uses the current chunk without
copying IDs. Explicit submission starts B1 when needed and invokes B4. Replies
play inline. **Continue course** rechecks A5 and applies replay/speed instructions;
the paused lesson remains paused until that explicit click. Frontend forms omit
playback-position input; Continue plays the current part from its beginning.
