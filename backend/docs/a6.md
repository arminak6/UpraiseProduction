# A6 - Cancel or acknowledge a job

`DELETE /v1/jobs/{job_id}?reason=CANCEL|RECEIVED`

The required `job_id` is a UUID. The required `reason` is a case-sensitive query
parameter. Success returns **204 No Content**. There is no request body.
This implementation operates on A1 ingestion and A3 lesson jobs. A3's adapter
purges its temporary JSON/audio/checkpoints and preserves all source PDFs and
Qdrant material. See [A3/A5](a3.md) for lesson TTL and callback acknowledgement.

INGRESS requires OAuth/mTLS and `jobs:write`, plus the job's client and course
access. Unknown, inaccessible or A2-deleted jobs return `404 JOB_NOT_FOUND`.
Explicit development/local testing includes this scope. A4 polling still uses
`jobs:read`; write permission must be included in production tokens separately.

## State transitions

| Reason | Allowed state | Result |
| --- | --- | --- |
| CANCEL | QUEUED or RUNNING | CANCELLED; worker ownership revoked; all unfinished vectors and temporary output removed |
| RECEIVED | DONE or FAILED | Acknowledged; terminal result/error and active ingested material preserved; temporary output and inactive vectors removed |
| Same reason again | Previously accepted action | Resume pending cleanup or return 204 after completion; audit is not duplicated |
| Different reason after an action | Any | 409 JOB_ACTION_CONFLICT |
| Other state/reason combination | Any | 409 JOB_ACTION_NOT_ALLOWED |

Cancellation does not delete a completed document. Use A2's
`DELETE /v1/documents/{document_id}` to remove ingested material. A failed job can
be acknowledged with RECEIVED to clear its temporary output. A canceled A1 retry
key returns `409 JOB_CANCELLED`; intentional reprocessing needs a new submission.

Original `source.pdf` files, job records, minimal results, metadata and audit
history remain available. A6 removes prepared extraction/embedding checkpoints,
partial checkpoints, crops, provider caches and native parser artifacts. RECEIVED
preserves the DONE job's `active_attempt` and its Qdrant vectors. Both actions
remove any inactive vector attempts with a course/document filter and verify
their absence. The existing explicit artifact retention setting can separately
remove retained sources later; it is disabled by default.

## Orchestration and recovery

1. INGRESS validates access; the orchestrator locks the job row and validates state.
2. It commits a durable cleanup request. CANCEL commits CANCELLED and clears
   the lease immediately, preventing claims, progress, retries or publication
   by the old worker. RECEIVED keeps the terminal status and active attempt.
3. A per-job file lock coordinates workers and cleanup across the shared volume.
   The orchestrator clears vectors/output only while no worker can write artifacts.
4. AUDIT records JOB_CANCELLED or JOB_RECEIVED without source text or credentials;
   stable event identities prevent duplicates. The cleanup completion commits,
   then the endpoint returns 204.

The worker supervisor observes cancellation or revoked ownership with bounded
status polling and stops its local child process, including a blocked parser.
It waits for confirmed child exit before allowing artifact cleanup. Cancellation
prevents later publication, but does not promise to abort an external provider
request already sent or prevent its billing.
While that worker holds the artifact lock, the endpoint returns
`503 JOB_CLEANUP_PENDING` with `Retry-After: 2`. A4 already shows CANCELLED and
`cleanup_pending: true`. This response does not undo cancellation. Retry the same
job ID and reason to obtain 204 once cleanup finishes.

Worker exit releases the file lock, including after a process crash. The supervisor
also enforces processing deadlines independently of child progress and heartbeats;
see [worker budgets](a1.md#recovery-and-limits). The worker completes pending cleanup
after the child stops and also polls durable cleanup
requests independently of ingestion pipeline compatibility. Filesystem, Qdrant
or audit/database outages return safe 503 errors and leave cleanup recoverable.
No 204 is returned before cleanup and audit complete. If publication wins the
job row lock first, the job becomes DONE and CANCEL returns 409; RECEIVED is then
the appropriate action.

A4 adds `cleanup_pending` and `acknowledged` booleans and supports CANCELLED.
Acknowledgment leaves A4 accessible. A2 lists canceled submissions with zero
active chunks and retains its separate deletion behavior.

## Testing

The Streamlit **Processing status** page has explicit CANCEL/RECEIVED controls
for the selected job and stops polling at CANCELLED. Swagger at
`http://localhost:8000/docs` also exposes the reason parameter.

Maintained tests use synthetic PDFs, deterministic providers and isolated real
PostgreSQL schemas/Qdrant collections. They verify worker fencing, publication
races, source and active-vector preservation, filesystem/vector/audit/commit
failure recovery, idempotent retries, access control, repeatable schema upgrades,
and artifact locking across processes including crash release.
