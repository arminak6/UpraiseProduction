# C5 — Deployed versions

`GET /v1/version` reports the configuration of the running AI module. It is
independent of C1/C2 health and availability.

`pipelines.generated_content_deletion` describes B7's provider-free workflow,
including selected-level support, preserved sources and its204 success status.
`pipelines.runtime_controls` identifies C3's durable kill-switch version, B2
adaptation bypass and shared admin-write limit. Current runtime switch values
are reported by C2/C3, not frozen into the C5 startup snapshot.

## Input and access

No request body, query parameters, course ID or learner session JWT.
Production requires the same service OAuth/mTLS authentication as C2.
The explicit development local-test mode also permits the call.

```powershell
curl.exe -i "http://localhost:8000/v1/version"
```

## Output

HTTP `200`, JSON, `Cache-Control: no-store`. See `VersionStatus` in
`src/upraise_ai/schemas/versions.py` and the live OpenAPI contract.

| Field | Meaning |
| --- | --- |
| `schema_version` | `c5-v1`, the metadata response contract |
| `application` | Application version, source/build fingerprint, installed relevant dependency versions |
| `models` | Configured Bedrock IDs by role, Polly engine, Transcribe provider |
| `prompts` | Prompt labels and SHA-256 hashes of maintained source bundles |
| `pipelines` | Effective ingestion/generation signatures, revision strategy, interruption version and selected nonsecret parameters |
| `cognitive_load` | Fusion status and the actual B2 threshold policy |
| `configuration_id` | SHA-256 fingerprint of the other response fields |

B2 currently reports `fusion_rule.status=NOT_IMPLEMENTED` and a
`fixed_threshold`, version `test-v1`, value `0.5`, comparison `>`.
Telemetry consent is required. A score equal to `0.5` returns `PROCEED`.
This identifies the agreed test policy, not a calibrated cognitive-load model.

Polly/Transcribe internal model releases are provider-managed: their model ID
is `null`. A configured Bedrock model ID is the exact ID requested by the code;
it does not prove an immutable provider weight revision or availability.
The retained legacy `lesson_visual_model_id` is not an active A3 model role.
Actual speech engines, including fallbacks, remain recorded in each lesson result.

`build_id` hashes the packaged backend Python source plus `pyproject.toml`,
`uv.lock` and the MathJax runtime source/dependency manifests. It normalizes
CRLF/LF and includes relative filenames. It identifies source and locked
dependencies, not the Docker image digest, Git commit or provider weights.
If manifests are unavailable, `build_id_kind` explicitly reports
`source_sha256`; an unreadable build has a null ID and `UNAVAILABLE`.
Missing installed dependency versions are null.

Prompt `sha256` uses `hash_kind=source_bundle_sha256`. Bundles include prompt
templates, inline policy, formatters and structured-output definitions; they
exclude per-request source text, teacher reviews and learner messages. A code
change in a bundle can change its hash without a manual prompt-label change.
Missing prompt sources or labels report `UNAVAILABLE`, not an invented version.

## Flow

1. Authenticate and authorize the service caller.
2. Read the process-start snapshot of packaged source and effective settings.
3. Return nonsecret model/prompt/pipeline/policy metadata and its fingerprint.

The GET does not call AWS inference, PostgreSQL or Qdrant and does not write an
audit event. Production ingress may contact the identity provider for JWT keys.
Models, source files and startup configuration are immutable for the process;
deploy/restart the affected services after changing them.

## Historical provenance

New A1 job results and A3 results/PostgreSQL prepared chunks retain
`configuration_id` and `build_id`. A7 retains the parent's generation metadata
and adds `revision_configuration_id`/`revision_build_id`; its A4 summary refers
to the revision configuration. A7 still changes only the selected chunk.
For an all-level A7 request, it changes that teaching unit's corresponding chunk
in each available level. `pipelines.revision.parameters.all_levels_supported`
reports this capability; each updated chunk retains its own revision references.
Revision parameters also report `alignment_review=teacher-feedback-aware-v1` and
`max_alignment_corrections=2` and `max_final_output_corrections=2`; prompt
`chunk-revision-v3` covers permitted cosmetic
edits and the corrective editor. Accepted/rejected reviews bind their exact
candidate text in A7 checkpoints and remain author output, not audit content.

New production audit events retain a complete content-free `version_snapshot`
from the component writing that event. Generation events identify generation
settings; a later read/end event identifies the component handling that read
or end. It does not relabel the older lesson. No learner score, chat/audio,
credential, private path or per-course control configuration enters C5.
Existing event IDs/idempotency and retention rules are preserved.

Prepared ingestion and lesson checkpoints also bind to this fingerprint, so
a retry cannot reuse text generated under different code/prompts and label it
as the current configuration. A7 fails a conflicting revision checkpoint rather
than silently replacing it. Drain active jobs before changing deployments.

Older jobs/audit rows are not backfilled: their original version metadata stays
unchanged. Current C5 alone cannot establish the configuration of an older job.
The metadata extends existing JSONB/version maps; no database migration is needed.

## Frontend and validation

The ingestion pipeline reports PDF/CSV support, csv-records-v1 and configured
CSV size/row/column limits. New ingestion signatures bind these settings.

Word DOCX/DOC formats, parser identity, upload/expanded limits, conversion timeout
and visual-fallback setting are also included in ingestion provenance.

The Streamlit **Health** page offers **Check versions**. It makes one explicit
GET and clears its previous response when the backend/credentials change.

`test_c5.py` checks deterministic fingerprints, policy/model/prompt/build changes,
secret exclusion, missing metadata, authorization and dependency-free reads.
`test_c5_integration.py` uses disposable PostgreSQL/Qdrant and fake providers
to verify A1/A3/A7 provenance, immutable older metadata and B2 policy audit
without recording its measurement. Frontend AppTest covers explicit C5 reads.
