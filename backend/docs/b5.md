# B5 - Stop or end a lesson session

`POST /v1/sessions/{session_id}/end` ends one B1 learner session. It clears
temporary learner conversation and B4 reply audio, preserving generated course
text/SSML in PostgreSQL, A3 course WAVs and Qdrant source material.

## Input and authorization

`session_id` is a UUID in the URL. The required JSON body has one field:

```json
{"reason":"STOPPED_BY_LEARNER"}
```

Accepted reasons: `COMPLETED`, `STOPPED_BY_LEARNER`, `TIMEOUT`, `ERROR`.
Unknown fields and invalid reasons are rejected with 422. Completion is reported
by the caller; this endpoint does not certify learning outcomes or last-chunk playback.

Service OAuth/mTLS ingress, client/course ownership and
the exact signed `X-UPRAISE-Session-JWT` binding apply, following B1/B4. Explicit
development/local preview permits JWT-free access to its own preview session.
Questions or telemetry consent is not required to stop a session. Language,
level, lesson/job and document IDs are already bound by B1 and need not be sent.

B5 does not read A5 output or require the source documents to remain available:
a learner can close their existing session after course output expiry/disposal.
Production callers still need a valid session assertion.

## Output and retries

Successful closure returns `204 No Content`, no body, `Cache-Control: no-store`.
Repeated authorized calls return 204 without a second end event while the bounded
RAM end record remains. The first reason and end timestamp are preserved even
if a retry sends a different reason. No additional request ID or idempotency key.

Content-free retry records retain the session binding, initial metadata, reason,
end timestamp and audit status for up to 30 minutes after ending (bounded to the
session capacity, oldest successfully audited records evicted first). They do not
retain conversation, answers, audio, chunk position or counters. Unknown, foreign,
evicted or restart-lost sessions return 404. An ended session ID cannot reopen B1
while its end record remains; start another session with a new UUID.

An audit outage returns sanitized 503 `AUDIT_STORAGE_UNAVAILABLE`. The session is
already closed and learner content cleared; a repeat B5 call or background sweep
retries the same end event. Pending audit records are not evicted; they consume
the admission budget until the audit recovers. RAM retry metadata is lost on
process restart, so an outage followed by restart can lose a pending end audit.
This preserves the current single-process, no durable learner-state architecture.

## Flow

1. Authorize the exact session binding, including ended-session retries.
2. Atomically remove the active session and clear chat, cached B4 responses/audio,
   request fingerprints, current chunk, cognitive-load placeholder and counters.
3. Retain only bounded, content-free retry metadata. New B4 requests fail with
   410 `SESSION_ENDED` (or `SESSION_EXPIRED` for timeout).
4. Write one `session_ended` audit containing session/course/activity/lesson IDs,
   reason and end time. The lesson job ID is the audit row's existing parent ID.
   No learner subject, JWT, message, answer or audio is written to audit.
5. Return 204 after audit success.

Ending does not wait for an in-flight model/STT/TTS call. Such a call can finish,
but B4 rechecks session state before subsequent provider stages/cache/delivery
and discards the answer. Already downloaded client files are outside backend RAM
cleanup; the frontend must stop players and discard its interruption reply state.

## Automatic expiry and course retention

The same session cleanup runs on fixed session expiry, recording `TIMEOUT` once.
The background sweep retries pending audits outside the event loop/global session
lock. Session lifetime still defaults to 30 minutes from B1 start, capped by
lesson/JWT expiry; it is not an inactivity timer and activity does not renew it.
Backend restart still clears all process-local sessions.

B5 never invokes A2 or A6 and never removes course JSON/WAVs, generated PG text,
source PDFs or vectors. A3's separate 24-hour output expiry and A6 disposal still
apply. Other learners and their audio caches are isolated.

## Frontend and local test

**Learning:** Finish course uses `COMPLETED`; Back to courses uses
`STOPPED_BY_LEARNER` for an open question session. If playback never opened B1,
there is no backend session to end. Both controls stop browser playback and clear
interruption answers/widgets. Failed closure keeps only the session ID/token and
reason needed to retry session end.

Start a new B1 session with an available lesson, then substitute its actual UUID:

```powershell
curl.exe --% -i -X POST "http://localhost:8000/v1/sessions/SESSION_UUID/end" -H "Content-Type: application/json" --data-raw "{\"reason\":\"STOPPED_BY_LEARNER\"}"
```

Expect 204; repeating the same call also returns 204. B4 on that session returns
410 while its end record remains; A5 course audio remains available until its
independent expiry/disposal. Production additionally requires the service bearer
token and the matching session JWT header.
