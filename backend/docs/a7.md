# A7 — Revise a teaching chunk and regenerate matching audio

User-approved contract, 2026-10-08. This extends the Word draft's audio-only A7:
the author supplies revision instructions; the module retrieves the current
teaching text and original sources, revises one chunk, and creates matching speech.

## Request

`POST /v1/audio:regenerate`, normal authoring INGRESS, `lessons:write`, same client
and authorized course as the parent generation. No learner session/JWT/consent
or learner Input Guard. Global/course generation and TTS controls apply.

```json
{
  "lesson_job_id": "3bb82b5e-423d-448c-a734-e8dd48b980ce",
  "chunk_id": "9819391d-f905-5fe4-b17e-4dfad43602cc",
  "teacher_review": "Explain these measurements more simply, preserve their values, and remove the final question."
}
```

Both IDs are UUIDs. Feedback is trimmed, nonblank, at most 8000 characters, and
cannot contain invalid control characters. Extra request fields are rejected.
The parent identifies the exact language, voice, explanation level, course,
activity, lesson and source scope; these are inherited, not caller overrides.
No `content_unit_id`, duplicate `lesson_id` or expected checksum is required.

The parent must be DONE, accessible, undisposed and unexpired with valid A5
JSON, matching PostgreSQL text/SSML and intact audio for every chunk. Unknown/
inaccessible parent or chunk returns404, unavailable result409, expired410,
invalid input422 and integrity/storage/provider-control problems503 or the
existing structured error. A running artifact writer may return retryable503
`JOB_CLEANUP_PENDING` before result readiness is checked.

## Acceptance, progress and result

Always asynchronous, including short text:

```http
HTTP/1.1 202 Accepted
Location: /v1/jobs/<new-job-id>
Cache-Control: no-store
```

```json
{"job_id":"<new-job-id>"}
```

A4 `GET /v1/jobs/{job_id}` reports SOURCE, GENERATE, REVIEW, FINALIZE, optional
TRANSLATE, SPEECH, PUBLISH and DONE, or normal retry/failure/cancellation.
A5 `GET /v1/jobs/{job_id}/result` returns a complete `LessonResult`: DRAFT,
inherited settings, ordered chunks containing text/SSML/audio URL/visemes/
duration/sources/reviewer reports, plus optional revision provenance:

```json
"revision": {
  "parent_job_id": "<parent-job-id>",
  "chunk_id": "<edited-chunk-id>",
  "number": 1
}
```

A4's result summary and A8's catalog also expose this content-free provenance.
The response never includes teacher feedback. `number` counts the parent lineage,
not an exclusive global edit sequence: independent edits of the same parent can
both be revision1. Chunk UUIDs remain the same within each version; identity is
the `(job_id, chunk_id)` pair. Unchanged chunks retain text, speech, ordering,
audio bytes and review findings. URLs identify the new job's independent files.

Download the WAV through the usual authenticated A5 audio endpoint. The JSON
contains an audio URL, not embedded base64 audio. New output expires24 hours
after completion by default, independently of the parent. A6 cancellation/
receipt and delivery cleanup apply unchanged. PostgreSQL teaching text/SSML
survive cleanup; A5 audio/JSON/checkpoints do not.

## Processing and consistency

1. Under a shared parent artifact lock and a parent job transaction, validate
   ownership, PostgreSQL/artifact consistency, active sources and all audio hashes.
   Stage an immutable complete lesson snapshot before the new job becomes visible.
   Hard-link immutable WAVs on the shared volume (copy fallback), so parent cleanup
   cannot delete the new version's copies. A failure before acceptance rolls back
   the job; uncertain commit outcomes retain artifacts for recovery.
2. Existing lesson workers claim A7 jobs using the same leases, process isolation,
   budgets and failure recovery as A3. Verify the snapshot hash and pinned source
   attempts; load the referenced Qdrant source IDs from the active authoritative
   documents. No PDF extraction, embedding or whole-lesson generation is repeated.
3. Use the same configured V3 models and generator/reviewer/editor roles with
   chunk-specific prompts. Supply current PostgreSQL teaching text, author feedback,
   canonical sources and adjacent teaching context. Neighbour context is capped
   at6000 characters per adjacent chunk; source evidence is never silently truncated.
   Source context above the existing configured budget fails. Final teaching text
   is capped at16000 characters; the selected chunk stays one chunk.
4. Generate/review/finalize in the source language at the inherited level. As in
   A3, the finalizer validates an approved draft without an extra model call, or
   performs one editor correction. Validate final citations and math markup.
   For a different lesson language, reuse A3's checked translation before storage
   and target-language speech. Draft review findings and source-quality warnings
   remain visible; AI review is not human approval or a post-edit quality guarantee.
5. Checkpoint finalized target text, then save the complete version's prepared
   text and exact SSML in PostgreSQL before TTS. Speech retries reuse finalized
   text; audio/viseme checkpoints avoid repeats after successful synthesis.
   Only the edited chunk is synthesized, using inherited voice/language and V3
   math preparation, engine fallback and timing validation.
6. Publish a new complete result only after audio is ready and source/lease checks
   pass. Audit REVISION_ACCEPTED/CHUNK_REVISED using IDs, revision and hashes only.
   Author feedback/teaching/source content are absent from audit/logging.

The parent result/hash/PG rows and active learner sessions are unchanged. A8 lists
both available versions; the frontend labels revisions explicitly. B1 can start
either unexpired version by its exact job ID. B4's PostgreSQL equality checks work
with the selected version. New DRAFT content requires external human approval
and a new matching production session JWT.

## Request retries

User explicitly deferred A7 `Idempotency-Key` support to future work. Every POST
creates a new job, including repeated bodies or repeated header keys. The frontend
submits only on explicit action, disables submission after acceptance and never
automatically retries an ambiguous POST. Worker retries of an existing job still
use checkpoints/fencing; provider calls remain at least once during crash recovery.
Existing A1/A3 idempotency behavior is unchanged. Backlog: FUTURE_UPDATES.md section3.

## Frontend and local curl

Streamlit's **Revise chunk (A7)** page loads an available lesson through A8/A5,
shows the selected teaching text and submits author feedback. **Processing status**
uses A4/A5 for progress, result/audio and A6. Completed versions appear in Learning.

One-line PowerShell request (the example parent must still be unexpired):

```powershell
curl.exe --% -i -X POST "http://localhost:8000/v1/audio:regenerate" -H "Content-Type: application/json" --data-raw "{\"lesson_job_id\":\"3bb82b5e-423d-448c-a734-e8dd48b980ce\",\"chunk_id\":\"9819391d-f905-5fe4-b17e-4dfad43602cc\",\"teacher_review\":\"Explain these measurements more simply, preserve their values, and remove the final question.\"}"
```
