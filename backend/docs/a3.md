# A3 — Generate draft lessons; A5 — Fetch result/audio

This page describes A3 v1 (one requested level). [A3 v2](a3-v2.md) generates all
configured levels from one shared chunk plan through `POST /v2/lesson-jobs`.
Both versions accept ingested PDF and CSV document IDs. CSV windows contain row
groups, and generated source references identify CSV records rather than PDF
pages; see [CSV ingestion](csv-ingestion.md).
Word DOCX/DOC sources also use ordered logical blocks and public Word block
citations. See [Word ingestion](word-ingestion.md).

Implemented from the user's A3 description and Uprise/v2 Version 3 workflow.
Outbound mTLS plus a short-lived OAuth2 token is a user-approved design addition
(2026-10-05), not a claim that the original Word draft specified it.

## Request and response

`POST /v1/lesson-jobs` uses OAuth/mTLS INGRESS and checks course access. Production fails closed; explicit development local mode also supports
A3/A5. A3 source access requires the same client identity and course as A1.

```json
{
  "lesson_id": "moodle-lesson-42",
  "course_id": "3",
  "activity_id": "7",
  "document_ids": ["00000000-0000-4000-8000-000000000001"],
  "language": "en",
  "voice": "Joanna",
  "options": {
    "source_window_pages": 5,
    "target_chunk_words": 200,
    "learner_level": "intermediate"
  },
  "callback_url": "https://middleware.example/ai/lesson-result"
}
```

All IDs except document UUIDs are opaque strings. `document_ids` is a unique,
ordered list (1–50). Unknown/inaccessible/deleted documents return 404; failed
or cancelled ingestion returns 409. Known pending A1 jobs are awaited by A3;
the independent A1 worker completes them. An ID alone cannot fetch an unknown
Moodle file: submit it through A1 first. Waiting defaults to 24 hours, then FAILED.

`source_window_pages` defaults to 5 (1–50); 6 selects pages 1–6, 7–12, etc.
Documents keep caller order; windows keep page order; source chunks keep their
ingestion order. A source chunk crossing a window is assigned once, with **all**
its pages retained for review. Empty windows produce no content. This option
does not change A1 chunking. Source windows exceeding the configured request
budget fail `LESSON_SOURCE_WINDOW_TOO_LARGE`; reduce the page window instead of
silently truncating evidence.

`target_chunk_words` defaults to 200 (30–1000). It is approximate: preserve
sentences, paragraph context and complete delimited formulas. Generated text
is finalized in A1's source language, then translated when necessary so the
stored lesson text and narration use A3's `language`. Voice compatibility is checked against the
configured Polly engine in the selected EU region; incompatible combinations
fail with `LESSON_VOICE_LANGUAGE_UNSUPPORTED`. Base language `en` permits the
voice's English variant; `en-GB` requires that exact variant.

`learner_level` controls the difficulty of the explanation and defaults to
`intermediate`. Every source window uses the requested level in the generator,
reviewer and editor's system messages:

- `beginner`: assume little familiarity, use plain language, introduce terminology
  and notation, and explain source-supported reasoning in small steps.
- `intermediate`: assume basic familiarity and balance intuition with technical
  detail, explaining new concepts and the key reasoning steps.
- `advanced`: assume a strong foundation, use precise terminology and notation,
  and give greater depth to source-supported reasoning, assumptions and limitations.

All levels retain substantive source coverage, factual accuracy, mathematical
meaning and citations. They do not authorize outside definitions or examples.
The reviewer records level mismatches as clarity/teaching-quality findings; the
editor repairs them at the same requested level. Prompt application is not a
guarantee of pedagogical suitability or human approval. New output reports
`learner_level_applied=true` and version `learner_level_prompt=explanation-level-v1`.
Earlier output keeps its original flag and text; submit a fresh A3 job/key to
generate at a requested level.

### Source and target languages

A1's stored `language` label identifies each document's source language. A3's
`language` identifies the requested teaching/audio language. A3 reads the label
from the authoritative ingestion record; it does not guess the PDF's language
or translate the Qdrant source material. Existing A1 records already have this
label and need no re-ingestion.

For example, A1 `language=en` and A3 `language=it`, `voice=Bianca`:

1. Generate, review and finalize each source window in English at the requested
   beginner/intermediate/advanced explanation level.
2. Translate the finalized teaching prose into Italian using the generator model.
   Immutable placeholders preserve every delimited formula, page citation and
   inline code span. Paragraph IDs, order and page provenance must remain intact.
3. Use the independent reviewer model to check target-language prose, preserved
   meaning/coverage and explanation difficulty on paired source/translated paragraphs.
   Language checks apply only to the translated prose; source language, notation
   and accepted technical loanwords are exempt. Both sides use identical opaque
   placeholders for code, citations and equations after exact equality checks;
   English inside an immutable LaTeX formula cannot trigger prose rejection.
   Every rejection must identify an
   actual translated passage and a concrete correction. Apply one bounded prose
   correction and independently review it again. Reject unresolved checks before
   PostgreSQL text writes or speech synthesis. This is an automated translation
   check; the lesson remains DRAFT and still needs external human approval.
4. Split the checked Italian text into approximately sized lesson chunks, commit
   that text to PostgreSQL, and create Italian SSML/audio with Bianca. A5 returns
   the same translated text that was saved and used for speech preparation.

Matching primary language tags skip translation and its two model calls, e.g.
`en` to `en-US` or `it-IT` to `it`. Exact regional voice compatibility is still
checked separately. Multiple documents use their own A1 labels: for an Italian
lesson, English sections are translated while Italian sections skip translation.
A missing stored source-language label fails `LESSON_SOURCE_LANGUAGE_MISSING`.

A4 can show `TRANSLATE` during generation. Invalid JSON, damaged placeholders or
invalid text produce `LESSON_TRANSLATION_INVALID`; truncated output produces
`LESSON_TRANSLATION_INCOMPLETE`; an echoed section or failed translation review
produces `LESSON_TRANSLATION_REJECTED`. These use the existing bounded job retry.
Content-free worker logs identify the specific check (e.g. `JSON_SCHEMA`,
`PARAGRAPH_IDS`, `PLACEHOLDER_SEQUENCE`, `NOTATION_CHANGED`, `WRONG_LANGUAGE`,
`REVIEW_EVIDENCE`). Review issues must cover each false field and quote the
identified translation paragraph exactly; unsupported reports fail closed.
Both the first candidate and the correction undergo all structural/notation checks.
Cross-language sections use two model calls normally, at most four when corrected,
per job attempt. The existing three-attempt job limit still applies.
These reason identifiers are logged even when raw-response capture is disabled.
The parser can recover one complete, schema-valid JSON object from an extra
opening brace, Markdown fence or explanatory wrapper. It rejects ambiguous
multiple payloads and never repairs strings, missing paragraphs or notation.
Truncated responses still fail before recovery; all content/provenance checks
and the independent translation review remain required. This handles the live
Bedrock wrapper error reproduced on 2026-10-06.
Separate finalized-source and checked-translation checkpoints avoid regenerating
the three-agent text after a translation failure, and avoid retranslating after
a speech/storage failure. Source labels are included in checkpoint signatures.

Stored chunk/A5 `versions` include `translation_prompt`, `translation_model`,
`translation_review_model`, `translation_applied` (string `true`/`false`) and
`source_languages`. The parent job still records target language, voice and level.
Provider JSON schemas use the [supported Bedrock subset](https://docs.aws.amazon.com/bedrock/latest/userguide/structured-output.html);
text/array/numeric bounds are checked locally. No translation is performed for
historical completed jobs; submit a fresh A3 job/key to generate translated output.

`callback_url` is optional for A5-only delivery. If supplied it must pass the
configured MW hostname allowlist and outbound authentication configuration.
No request-supplied secrets or unsigned audio URLs are accepted.

Acceptance is HTTP **202** with only `{"job_id":"…"}` and
`Location: /v1/jobs/{job_id}`. `Idempotency-Key` protects network retries; a
different request with the same key is 409. A new key permits another generation
for the same `lesson_id`. A disposed key is 409; use a new key for regeneration.

## Processing and quality

1. Wait for known pending A1 jobs and read all active source chunks in caller
   order. Sources retain their original quality flags and complete provenance.
2. Divide sources into the requested page windows without truncating content.
3. Call the copied V3 teacher's explain, review_explanation and
   finalize_explanation methods. The A3 adapter adds the requested explanation
   level and role-specific teaching instructions to each system message, including
   formatting-recovery calls. V3's original base prompts, schemas, token limits,
   temperatures and formatting recovery remain intact. Non-English source labels also
   add the full source-language name. Math narration uses the target language
   without the course-generation level instructions.
4. V3 normalizes draft citations, then sends the draft to its source-text
   reviewer. Draft citations are not rejected before that reviewer can request
   repair. Finalization always runs: an approved draft is validated directly;
   a rejected draft receives one editor revision and final citation/math checks.
   The generation stage adds no extra PDF judge or post-edit source review.
   The separate translation check compares finalized source text to its translation.
5. Adapt the final TeacherTurn to A3 paragraphs, translate/check when the source
   and requested primary languages differ, then create approximately sized output
   chunks, keeping formulas atomic and whole-window source provenance. Map the
   original review findings into the public ReviewReport and add extraction
   quality findings. Reports describe the pre-edit source review; a revision
   does not certify that all earlier findings were resolved.
6. Use V3 speech preparation: remove spoken Markdown/citations, batch formulas
   through MathJax/ClearSpeak, and use its reviewed contextual narration fallback.
   If contextual narration is unavailable, preserve V3's deterministic or
   structural fallback and add a speech issue for human review.
7. Use V3's PCM/WAV synthesis and standard-engine fallback. A3's adapter exports
   SSML and makes an additional Polly viseme request with the same SSML, voice,
   actual engine and language as each audio segment. Offset marks by preceding
   PCM duration. Valid marks whose independent timeline exceeds their segment
   are rescaled to fit its PCM duration, with an explicit speech finding.
   Malformed marks, missing marks and provider failures remain retryable errors.
8. Publish with the existing source activation checks, fencing, audit and DONE
   commit. The business status remains DRAFT and requires human approval.

The copied implementation is in services/v3/ with original source hashes in
origin.json. The teacher, models and prompts are unchanged. Speech/math modules
only relocate their SHA utility import and runtime directory; their original
function bodies are preserved. Shared math_speech_v4 helpers are used by V3's
teacher for final markup checks; A3 selects V3's speech class and fallback.

Defaults retain V3's GPT OSS generator and Qwen reviewer. Nova remains part of
A1 ingestion; the old lesson_visual_model_id setting is retained for configuration
compatibility but is unused by A3. Result versions mark visual review as
not-used-v3 and record the actual Polly engines used. AWS clients explicitly use
the configured EU region.

The lesson report aggregates section/chunk findings. It does not add a global
semantic consistency review. Positive model review and AUTO_CHECKED extraction
do not establish human-approved teaching accuracy.

## V3 compatibility and local diagnostics

The original V3 draft uses prose, 3000 output tokens and temperature 0.2.
Structured review/editor requests use Bedrock outputConfig, followed by V3's
bounded prompt-only formatting fallback. Original wrapper/LaTeX recovery and
final validation are retained; these fallback calls do not add revision cycles.

Paragraphs preserve the whole source window's pages, as TeacherTurn did. Display
text keeps citations, Markdown and notation; speech preparation protects math
spans before prose cleanup. A3 still controls document IDs, language, voice,
source page windows, output word targets, temporary results and callbacks.

Default logs exclude generated content. Optional
UPRAISE_LESSON_CAPTURE_MODEL_OUTPUTS=true requires development plus
local_test_mode; other modes refuse startup. Failed replies and validation
details are stored in the lesson's model-diagnostics folder and removed by
ordinary A6/TTL cleanup. Raw capture is off by default.
Translation diagnostics retain candidate and reviewer replies together, including
the bounded correction, rather than only the last verifier reply.

Pipeline identity is lesson-v3-a3-8; translation policy version is
`finalized-lesson-translation-v3`. Old checkpoints are not reused. Existing
failed jobs remain failed history: submit a fresh request/idempotency key to
retry. Public request/result schemas, routes, access checks and options remain
unchanged. Existing source documents need no re-ingestion.



## A4 and A5

[A5 pull-mode download contract](a5.md) describes per-request AUDIT, concurrent
read access, expiry and local download commands.

`GET /v1/jobs/{job_id}` reports QUEUED/RUNNING/DONE/FAILED/CANCELLED,
step, progress, attempts, safe error code, summary, lesson_id, expires_at,
callback status/attempts/error and cleanup/acknowledgement state. `DONE` means
the DRAFT artifacts exist, not that a reviewer or teacher approved them.

`GET /v1/jobs/{job_id}/result` returns a `LessonResult` containing:
lesson/course/activity IDs, status DRAFT, label AI-generated, language, voice,
level, ordered chunks, whole-lesson report, model/prompt/runtime versions and
expiry. A3 assigns job-specific chunk UUIDs; A7 keeps those UUIDs in new versions,
so the full identity is `(job_id, chunk_id)`. Each chunk has a **zero-based** index, text,
SSML, exact `ssml_parts`, audio URL/media type/SHA-256, duration in **seconds**,
visemes `{time_ms,value}` from the start of that chunk, document/version/page/
source-chunk provenance, V3 source reviewer report, section index and 0/1 revisions.

`GET /v1/jobs/{job_id}/audio/{chunk_id}` streams WAV bytes. URLs
use the configured public AI gateway, or relative paths in pull-only local use.
They require the ordinary MW → AI OAuth/mTLS credentials. Authenticated requests
cannot fetch another client's/course's artifacts. Pending/failed/cancelled
results return 409; disposed/expired output returns 410. Hash mismatch or missing
committed files returns 503. Source deletion also revokes result retrieval.

## Callback authentication and retries

Configure `.env.example`'s `UPRAISE_CALLBACK_*` values, a dedicated AI OAuth client
at the MW's identity provider, and the AI's outbound mTLS certificate/key. The
tracked `callback_tls/README.md` explains secret mounts. The backend validates
configuration; lesson workers mount the secret directory and delivery uses it. Configure
`UPRAISE_LESSON_PUBLIC_BASE_URL` as the externally reachable AI gateway URL.

Each delivery attempt obtains a new OAuth2 client-credentials bearer token
over mTLS, with configured scope (default `lessons:deliver`). It must have
`expires_in > 30` and `<= 900` seconds. Both the token endpoint and callback use
TLS server verification and the AI client certificate. Secret credentials are
deployment configuration, never job inputs, artifact JSON or audit content.
OAuth client authentication defaults to `client_secret_basic`; configure
`client_secret_post` or `tls_client_auth` when required by the identity provider.
Certificate client authentication requires client_id and mTLS, with no secret.

Callbacks allow HTTPS port 443 only, explicit MW hostnames, no URL credentials,
fragments or redirects. DNS addresses are checked and pinned with the original
TLS hostname; private destinations need explicit CIDRs. Loopback, link-local,
multicast and unspecified destinations remain forbidden. The token endpoint is
an operator-configured HTTPS URL, not a caller-provided destination.

The callback POST body is:

```json
{"job_id":"…","lesson_id":"…","status":"DONE","result":{"status":"DRAFT","chunks":[]},"error":null}
```

FAILED jobs send `result:null` and a safe error code. Completion delivery has
`Idempotency-Key: lesson-result-{job_id}`; MW must deduplicate it. Delivery is
at least once, defaults to 8 attempts with bounded exponential delay, and has
independent callback leases and killable 90-second attempts. A crash or timeout
can repeat an already received callback. Exhausted delivery is visible in A4;
the completed DRAFT is still available through A5 until expiry.

A callback **2xx does not delete output**. MW downloads JSON/audio, stores its
own permanent copy, then calls `DELETE /v1/jobs/{job_id}?reason=RECEIVED` (A6).

## Durability, cleanup and large documents

`lesson_jobs` stores operational metadata/state/summaries in upraise_jobs;
`prepared_lesson_chunks` now retains finalized lesson text in the same database,
following the user's 2026-10-06 request to preserve the text used for speech as
in Uprise/v2. Each row is keyed by job UUID and chunk UUID, with a unique ordered
chunk index, section index, source document/version/pages, pre-edit reviewer
report, revision count and generation model/prompt versions. Request IDs,
language, voice and client ownership remain on the parent `lesson_jobs` row.
This is a deliberate change from the September draft's temporary-only lesson
storage. Every saved lesson remains DRAFT; retention does not imply approval.

The worker commits all finalized, optionally translated chunk text before the first TTS synthesis, then
commits each chunk's SSML and exact SSML request parts before its synthesis.
Display text preserves Markdown, citations and equations; SSML records the
spoken transformation, including mathematical narration. A storage outage
prevents synthesis and is retried through the existing checkpoints. Writes
require a valid job lease and active source records. Retrying the same content
does not create duplicate rows; conflicting text under the same chunk identity
fails explicitly rather than overwriting already saved text.

Saved PostgreSQL text/SSML survives RECEIVED, CANCEL and TTL cleanup, including
finalized chunks of a job whose speech later fails or is cancelled. Inspect the
parent job status before treating an archive as a complete lesson. Existing
completed/disposed jobs are not backfilled automatically; text whose temporary
files were already deleted cannot be recovered by this change. A2 removes source
vectors but does not erase saved lesson text/history. There is currently no
public archive-read or archive-erasure API; authenticated operator SQL access
can join `prepared_lesson_chunks.job_id` to `lesson_jobs.job_id`. No audio bytes
are stored in PostgreSQL.

`lesson_audit` still stores content-free lifecycle events in upraise_audit.
Downloadable JSON, reports, job-bound checkpoints and audio remain in temporary
job folders on the shared volume. Section/audio checkpoints bind the complete source
identity, request and pipeline configuration; retries reuse completed work.

The dedicated `lesson-worker` spawns each job in a killable process with leases,
fencing, cancellation and workload deadlines. Default budget is 1200 seconds
per section, 180 per output chunk, plus phase overhead, bounded by a 12-hour
attempt maximum. A 200-page PDF gets about 40 default source windows and a
generous budget; elapsed time remains bounded. Tune with real workloads.
Three attempts are the existing retry default. Completed checkpoints survive
retryable failures; sent provider calls can still finish/bill after termination.

Independent `lesson-delivery` handles callbacks, expiry and interrupted A6
cleanup so generation cannot block them. TTL defaults to **24 hours from
completion**, configurable. A5 stops serving output at expiry immediately;
physical deletion and audit are recoverable and occur on delivery-worker polls
(active I/O/dependency outages can delay physical cleanup). RECEIVED/CANCEL
fence writers, take the artifact lock, remove only lesson JSON/audio/checkpoints,
and audit before 204. Busy cleanup returns 503 `JOB_CLEANUP_PENDING` with
Retry-After:2. Acknowledgement and expiry preserve source PDFs, Qdrant course
content, saved PostgreSQL lesson text/SSML and content-free job/audit history.
The A5 endpoints continue to return 410 after receipt/expiry even when text is
retained in PostgreSQL. No learner state is introduced.

Upgrade using `docker compose up --build -d --wait --wait-timeout 180` (add
`--profile tools` before `up` for Frontend2). Migration adds lesson tables without
resetting volumes. Drain old lesson jobs before changing model/pipeline settings;
workers claim only compatible recorded signatures. Do not re-ingest existing
documents to activate A3. Actual AWS/IAM, MW OAuth/mTLS and callback connectivity
need deployment configuration and an integration trial.
