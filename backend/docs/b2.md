# B2 - Chunk-end decision

`POST /v1/sessions/{session_id}/chunk-end`

Implemented on 2026-10-09 using the user-approved input measurement and a simple
test threshold. This is a synchronous playback decision; it does not estimate
cognitive load with a model. Middleware supplies the measurement. B3/B6 remain
reserved, and future scoring/telemetry policy can replace this threshold.

## Input and authorization

```json
{
  "lesson_id": "english-a7-test",
  "chunk_id": "19d722a4-3413-5079-8da9-611af9152591",
  "cognitive_load_score": 0.7
}
```

All three fields are required. `lesson_id` must match B1; `chunk_id` must be one
of the ordered chunks pinned by B1 to its exact `lesson_job_id`. The score is a
finite JSON number from 0 through 1; booleans, strings, null, extra fields and
the earlier name `chunk_index` are rejected with 422. Actual chunk indexes
remain zero-based integers derived by the backend.

Uses the same OAuth/mTLS INGRESS, `sessions:write` scope, client/course isolation
and `X-UPRAISE-Session-JWT` binding as B4/B5. Explicit local draft previews may
omit the session JWT. Questions consent is not required. Without B1's verified
`telemetry` consent, B2 always returns PROCEED and discards the measurement.
Consent cannot be supplied or overridden in B2's body.

## Output and flow

HTTP 200, `Cache-Control: no-store`, with exactly one field:

```json
{"decision": "HIGH_COGNITIVE_LOAD"}
```

With telemetry consent: score > 0.5 gives HIGH_COGNITIVE_LOAD; score <= 0.5
gives PROCEED. In particular, exactly 0.5 gives PROCEED.
If C3/deployment controls disable `adaptive_levels` or activate a global/course
`all` switch, an authorized B2 request always returns PROCEED and discards the
score. The control is rechecked after audit I/O; it does not change the B1-pinned
start level. See [C3](c3.md). Unavailable configured control storage returns 503
`OPERATIONS_STORAGE_UNAVAILABLE` before committing position/score.

1. Authorize the active B1 session and validate its lesson/chunk binding.
2. Record `chunk_ended` with session/chunk IDs and the content-free C5 deployment
   snapshot in the existing audit table.
   No score, decision, credentials, text or audio is persisted in audit.
3. Recheck that B5, fixed TTL expiry or shutdown has not closed the session.
4. Update the current chunk position and latest consented score in RAM, then
   return the decision. Do not renew the session's existing fixed TTL.

No Input Guard, LLM, RAG, Qdrant call, PostgreSQL teaching-text read, STT or TTS.
B2 reads the small shared control table in addition to its existing audit write.
B1 already pins the chunk IDs. Playback/content availability remains A5's
responsibility. Middleware decides whether to pause or proceed; the endpoint
does not move the player or generate a support response.

Only the latest score is retained, with no history or persistent learner data.
B5/TTL/restart clears it. Audit I/O stays outside the global session lock;
an in-flight B2 cannot restore cleared state after B5. A repeated request is safe
and recomputes the decision, but creates another content-free audit event.
No new database schema/migration or background worker is needed.

## Errors

- 401/403: missing/invalid JWT, scope or binding authorization.
- 404: SESSION_NOT_FOUND or LESSON_CHUNK_NOT_FOUND (foreign sessions are hidden).
- 409: SESSION_LESSON_MISMATCH.
- 410: SESSION_EXPIRED or SESSION_ENDED.
- 422: malformed IDs, missing/extra fields or invalid score.
- 503: LESSON_STORAGE_NOT_CONFIGURED or AUDIT_STORAGE_UNAVAILABLE. An audit
  failure leaves the score/position uncommitted; the caller can retry.

The local decision requires no provider latency. Audit/gateway/storage latency
still affects response time, so an absolute 300 ms bound is not guaranteed.

## Local test

These IDs reference the generated English test lesson; its A5 output must still
be available when B1 starts. Substitute actual IDs if testing another version.
Start B1 with telemetry consent, then test both score values:

```powershell
curl.exe --% -i -X POST "http://localhost:8000/v1/sessions" -H "Content-Type: application/json" --data-raw "{\"session_id\":\"9f2f20e8-f8b9-4cbf-9b4e-c06b7d26743c\",\"course_id\":\"test-course\",\"activity_id\":\"test-activity\",\"lesson_id\":\"english-a7-test\",\"lesson_job_id\":\"51e8c520-700d-4a0d-98db-e2eb6867c299\",\"consent_scope\":[\"telemetry\"]}"
curl.exe --% -i -X POST "http://localhost:8000/v1/sessions/9f2f20e8-f8b9-4cbf-9b4e-c06b7d26743c/chunk-end" -H "Content-Type: application/json" --data-raw "{\"lesson_id\":\"english-a7-test\",\"chunk_id\":\"19d722a4-3413-5079-8da9-611af9152591\",\"cognitive_load_score\":0.7}"
curl.exe --% -i -X POST "http://localhost:8000/v1/sessions/9f2f20e8-f8b9-4cbf-9b4e-c06b7d26743c/chunk-end" -H "Content-Type: application/json" --data-raw "{\"lesson_id\":\"english-a7-test\",\"chunk_id\":\"19d722a4-3413-5079-8da9-611af9152591\",\"cognitive_load_score\":0.3}"
```

The frontend's **Chunk end (B2)** page sends requests only on an explicit click.
It can prefill the B1 session/lesson; paste the A5 chunk UUID and enter a score.
It displays the HTTP decision without automatically changing course playback.
Credential, B1 session or input changes clear the old result; B5 clears the
matching cached measurement/decision.
