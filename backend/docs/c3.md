# C3 — Runtime kill switch

`PUT /v1/admin/kill-switch` changes an operator disable without restarting the
API or workers. State persists in PostgreSQL and is shared across processes.
This endpoint does not change deployment environment settings.

## Authorization and input

Production requires the existing OAuth/mTLS INGRESS plus the dedicated
`admin:operations` OAuth scope. Ordinary authoring/session/job scopes do not
grant administration. A course-scoped change also requires that course in the
caller's signed course claims. The admin scope grants global control.

```json
{
  "scope": "course_id",
  "course_id": "course-1",
  "feature": "answers",
  "enabled": true
}
```

- `scope`: `global` or `course_id`. Global requests omit `course_id` (null is
  accepted); course requests require a nonempty, unpadded ID of at most 120 characters.
- `feature`: `answers`, `generation`, `adaptive_levels`, or `all`. The existing
  independent `stt` and `tts` controls are supported too.
- `enabled`: strict JSON boolean. **True activates the kill switch and disables
  the feature; false releases that particular runtime switch.** Strings/numbers
  and unknown fields are rejected.

Global example:

```json
{"scope":"global","feature":"all","enabled":true}
```

Release that same switch with `enabled:false`. Runtime switches combine with
global/course deployment disables; releasing a runtime switch cannot override
another active switch or a deployment disable. `all` is an independent umbrella
switch: releasing it does not clear separately set feature switches.

## Response

HTTP 200, `Cache-Control: no-store`:

```json
{
  "scope": "course_id",
  "course_id": "course-1",
  "feature": "answers",
  "enabled": true,
  "kill_switch_active": false,
  "features_enabled": {
    "answers": false,
    "stt": true,
    "tts": true,
    "generation": true,
    "adaptive_levels": true
  },
  "updated_at": "2026-10-14T12:00:00Z",
  "audit_event_id": "60390722-dbcf-4007-af35-3d3db0d7da17",
  "audit_pending": false
}
```

`enabled` describes the selected runtime switch. `features_enabled` describes
the effective direct controls for the requested scope, including deployment
settings. It does not assert provider availability or dependencies between
features; C2 reports those. For example, disabled answers make STT/TTS
interruptions unavailable even when their individual switches are released.
`kill_switch_active` reports a global/course `all` switch, including the existing
deployment kill switches.

## Enforcement

- API admission reads current shared state; C2 also reads it for each request.
  A configured but unavailable/unmigrated control store returns sanitized 503;
  requests do not fall back to a previously enabled state.
- `all` blocks new A1/A3/A7/B4 AI work. `generation` blocks new A3/A7 work.
  Disabled answers/STT are rejected before their provider operations. Disabled
  B4 TTS keeps answer text with `AUDIO_DISABLED`.
- Workers read state each poll and exclude disabled courses before claiming jobs.
  A change racing initial child admission returns the job to QUEUED with
  `CONTROL_PAUSED`, without consuming an attempt. Releasing the switch allows
  normal polling to resume work. Cleanup and delivery remain operational.
- `adaptive_levels` off (or `all` active) makes authorized B2 chunk-end requests
  return `PROCEED` and discard the measurement. State is checked after audit I/O
  before committing the decision. Session consent, IDs, fixed TTL and pinned
  start level remain enforced. Other courses retain their normal B2 behavior.
- Existing A5 course playback and A2/A6/B5/B7 management remain available under
  their existing authorization/retention rules.
- A switch does not forcibly terminate a provider call or an already admitted
  generation attempt. It takes effect at subsequent control checks. Use A6 to
  cancel a specific job. There is no set-end API or automatic mid-session level
  switching in the current project; C3 does not introduce either.

## Durable state, audit and limits

The additive migration creates `operational_controls` and
`operational_control_events` in the jobs database, and `admin_audit` in the audit
database. Each successful PUT commits its state and durable audit event together
in one jobs-database transaction. A failed event insert rolls back the change.

The event records scope/feature, previous/new switch value, operator client ID,
timestamp, control version and the C5 deployment snapshot. It contains no bearer
token, learner identity, content, audio or cognitive-load scores.

The event is copied idempotently to `admin_audit` as `KILL_SWITCH_UPDATED`. If
the separate audit database is unavailable, HTTP 200 still confirms the applied,
durably audited change with `audit_pending:true`. The normal operations refresh
retries up to 100 pending events per cycle, including after a restart. Duplicate
PUTs preserve the requested state but record separate successful admin requests.

Writes are serialized and limited to 30 successful PUTs per minute per operator
client, shared across API processes. The 31st returns 429 `ADMIN_RATE_LIMITED`
with `Retry-After: 60`, without changing state. At most 1000 course IDs can have
active runtime switches; a new course beyond that returns 409
`OPERATIONAL_COURSE_LIMIT_REACHED`. Releasing a course's last switch frees its slot.
This API does not configure general gateway/request rate limits.

## Local testing and rollout

Default local testing does **not** grant the admin scope. To explicitly allow C3
on a development instance, set all three values and recreate the backend:

```dotenv
UPRAISE_ENVIRONMENT=development
UPRAISE_LOCAL_TEST_MODE=true
UPRAISE_OPERATIONS_LOCAL_ADMIN=true
```

The additional option is false by default and is rejected outside development
local test mode. Production must use a signed operator token. The existing
private/loopback socket-peer requirement still applies to local administration.

Drain active generation/ingestion before replacing the running images. Rebuild,
apply the additive schema, then refresh API/UI/workers together:

```sh
docker compose build backend frontend
docker compose run --rm --no-deps migrate
docker compose --profile tools up -d --no-deps --wait --wait-timeout 180 backend frontend worker lesson-worker lesson-delivery
```

Restarting clears existing RAM learner sessions. Source vectors, prepared text,
plans and unexpired course audio are preserved. Existing images must be migrated
and refreshed together; C3 needs the new control tables.

The frontend Health page has a C3 form with explicit target/action confirmation.
It sends only on Apply; rerenders/navigation never resubmit. Changed credentials,
scope/course/feature/action clear confirmation and old results. Successful writes
clear cached C2 status. The existing API explorer also exposes the PUT contract.

Other errors: 401/403 authentication/scope/course/local-admin denial; 422 malformed
body; 503 `OPERATIONS_STORAGE_NOT_CONFIGURED` or `OPERATIONS_STORAGE_UNAVAILABLE`.
No LLM, embedding, STT or TTS requests are made by C3 itself.
